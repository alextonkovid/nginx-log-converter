## Nginx log to CSV converter

This repository contains a python3 script that converts Nginx access logs into CSV files.
The parser is configurable via a YAML file, so it can be adapted to different
`log_format` definitions without changing the code.

### Requirements

- python 3.8+ (tested with python 3.x)
- `PyYAML` for reading the YAML configuration:

```bash
pip install pyyaml
```

### Files

- `nginx_log_to_csv.py` — main script that reads Nginx logs and writes CSV.
- `nginx_log_to_csv.yaml` — default parser configuration (regex pattern and field list)
  matching the current `nginx.log` format.
- `nginx.log` — example Nginx access log.
- `nginx.csv` / `nginx_selected.csv` — example CSV outputs generated by the script.

### YAML configuration

The parser is driven by a YAML config with two keys:

- `pattern` — a regular expression describing the structure of a single log line.
- `fieldnames` — list of field names in the same order as regex groups.

Example (matching the current sample log):

```yaml
pattern: '^(\S+)\s+(\S+)\s+(\S+)\s+\[([^\]]+)\]\s+"([^"]*)"\s+(\d{3})\s+(\d+)\s+"([^"]*)"\s+"([^"]*)"\s+(\d+)\s+([\d.]+)\s+\[([^\]]*)\]\s+\[([^\]]*)\]\s+(\S+)\s+(\d+)\s+([\d.]+)\s+(\d{3})\s+(\S+)$'
fieldnames:
  - client_ip
  - remote_ident
  - remote_user
  - time_local
  - request
  - status
  - body_bytes_sent
  - http_referer
  - http_user_agent
  - request_length
  - request_time
  - proxy_upstream_name
  - proxy_alternative_upstream_name
  - upstream_addr
  - upstream_response_length
  - upstream_response_time
  - upstream_status
  - request_id
```

If you change the Nginx `log_format`, you can adjust the `pattern` and `fieldnames`
in this YAML file instead of modifying the python3 code.

If the config file is missing or invalid, the script falls back to a built‑in
default pattern and field list compatible with the provided `nginx.log`.

### Basic usage

Convert a log file to CSV using the default YAML config (`nginx_log_to_csv.yaml`):

```bash
python3 nginx_log_to_csv.py nginx.log nginx.csv
```

Specify a custom config file:

```bash
python3 nginx_log_to_csv.py access.log access.csv --config custom_format.yaml
```

### Filtering

You can filter rows by exact field values using `--filter FIELD=VALUE`.
Multiple filters are combined with logical AND.

Examples:

```bash
# Only status 200
python3 nginx_log_to_csv.py nginx.log nginx_200.csv --filter status=200

# Status 200 AND specific client IP
python3 nginx_log_to_csv.py nginx.log nginx_filtered.csv \
  --filter status=200 \
  --filter client_ip=127.0.0.1
```

If a filter is malformed (does not contain `=`), it is ignored with a warning.

### Sorting

Use `--sort-by` to sort rows by one or more fields (lexicographically),
and `--desc` to reverse the sort order.

Examples:

```bash
# Sort by time_local ascending
python3 nginx_log_to_csv.py nginx.log nginx_sorted.csv \
  --sort-by time_local

# Sort by time_local, then status, descending
python3 nginx_log_to_csv.py nginx.log nginx_sorted.csv \
  --sort-by time_local,status \
  --desc
```

### Selecting columns for export

The script always parses all fields defined in the YAML config, but you can
choose which columns to include in the CSV output using `--columns`.

`--columns` accepts a comma‑separated list of field names that must exist
in the `fieldnames` from the config.

Example:

```bash
# Export only client_ip, request and status
python3 nginx_log_to_csv.py nginx.log nginx_selected.csv \
  --columns client_ip,request,status
```

If you specify unknown columns, they are ignored with a warning and only valid
columns are used. If no valid columns are found, the script falls back to
exporting all fields defined in the config.

### Typical workflow

1. Adjust Nginx `log_format` if needed.
2. Update `nginx_log_to_csv.yaml` (`pattern` and `fieldnames`) to match
   the new format.
3. Run `nginx_log_to_csv.py` with optional filters, sorting and `--columns`
   to generate the CSV file you need.

### Automatic Git push

The script can automatically commit and push the generated CSV file to a Git
repository after successful conversion. This is enabled by default if a `.env`
file with Git configuration is present.

#### Configuration

Create a `.env` file in the same directory as the script with the following
variables:

```env
GIT_REPO_URL=https://<token>@github.com/USER/REPO.git
GIT_BRANCH=main
GIT_REPO_DIR=repo
```

- **`GIT_REPO_URL`** (required): Full Git repository URL. Include authentication
  credentials (token or username:password) in the URL.
- **`GIT_BRANCH`** (optional): Branch name to push to. Defaults to `main`.
- **`GIT_REPO_DIR`** (optional): Local directory name for the cloned repository.
  Defaults to `repo`.

#### Usage

When `.env` is configured, the script will automatically:
1. Clone the repository (if the directory doesn't exist)
2. Copy the generated CSV file to the repository
3. Commit the changes with a message like "Update CSV: nginx.csv"
4. Push to the specified branch

Example:

```bash
# CSV will be automatically pushed to Git after generation
python3 nginx_log_to_csv.py nginx.log nginx.csv
```

To disable automatic Git push:

```bash
python3 nginx_log_to_csv.py nginx.log nginx.csv --no-git-push
```

To use a custom `.env` file:

```bash
python3 nginx_log_to_csv.py nginx.log nginx.csv --env-file /path/to/git.env
```

**Note**: If `.env` is missing or `GIT_REPO_URL` is not set, the script will
skip Git operations and only generate the CSV file.

### Using Docker

You can also run the converter using Docker instead of a local Python installation.

#### Build the image

From the repository root:

```bash
docker build -t nginx-log-to-csv .
```

#### Run the converter with Docker

Mount the current directory into the container (so it can access `nginx.log`
and write the CSV output), then pass the same arguments as to the python3 script:

```bash
docker run --rm -v "$(pwd)":/data nginx-log-to-csv \
  nginx.log nginx.csv
```

You can still use all CLI options (`--config`, `--filter`, `--sort-by`, `--desc`,
`--columns`) when running via Docker:

```bash
docker run --rm -v "$(pwd)":/data nginx-log-to-csv \
  nginx.log nginx_selected.csv \
  --columns client_ip,request,status \
  --filter status=200 \
  --sort-by time_local
```

#### Using `.env` file with Docker

To enable automatic Git push in Docker, you need to make the `.env` file available
inside the container. There are two ways to do this:

**Option 1: Mount `.env` file as volume** (recommended)

Since you're already mounting the current directory (`-v "$(pwd)":/data`), the `.env`
file will be automatically available if it's in the same directory:

```bash
docker run --rm -v "$(pwd)":/data nginx-log-to-csv \
  nginx.log nginx.csv
```

The script will look for `.env` in `/data` (which is your mounted directory).

**Option 2: Use Docker's `--env-file` flag**

You can also use Docker's built-in `--env-file` option, but note that the script
expects the file to be named `.env` in the working directory. You'll need to
specify the path explicitly:

```bash
docker run --rm -v "$(pwd)":/data --env-file .env nginx-log-to-csv \
  nginx.log nginx.csv --env-file /data/.env
```

Or mount the `.env` file separately:

```bash
docker run --rm \
  -v "$(pwd)":/data \
  -v "$(pwd)/.env":/data/.env \
  nginx-log-to-csv \
  nginx.log nginx.csv
```

**Option 3: Pass environment variables directly**

You can also pass Git configuration as environment variables:

```bash
docker run --rm \
  -v "$(pwd)":/data \
  -e GIT_REPO_URL="https://token@github.com/user/repo.git" \
  -e GIT_BRANCH="main" \
  -e GIT_REPO_DIR="repo" \
  nginx-log-to-csv \
  nginx.log nginx.csv
```

**Note**: When using Docker, make sure your `.env` file is in the directory you're
mounting to `/data`. The script will look for `.env` in the current working
directory (`/data` by default).

On Windows PowerShell, the volume flag would typically look like:

```powershell
docker run --rm -v "${PWD}:/data" nginx-log-to-csv `
  nginx.log nginx.csv
```
